# LightOverLeaf 前端体验与视觉优化开发方案

日期：2026-09-17
状态：评审与实施计划，尚未修改界面代码。
范围：Electron + TypeScript + React 工作台，保留 C++ 原生业务与现有 RPC。

## 1. 结论与证据边界

当前前端已经具备写作工作台的基本结构，主要问题不是缺少装饰，而是字号与操作密度、主操作可达性、状态反馈和组件规则不统一。建议保留深色灰蓝底色与绿色品牌强调，先消除操作障碍，再统一视觉，最后补充效率功能。不要整体重写编辑器与 PDF 管线。

本次检查覆盖 main.tsx、两份工作台 CSS、Header、布局状态、文件树、设置、菜单、Monaco、PDF 预览、日志与 Electron 窗口配置。旧对话中的截图仅作历史视觉线索，不能代表当前版本。

实际情况：本地 Vite 服务启动成功；浏览器控制工具两次因本机运行环境错误退出，未完成当前版本截图、鼠标操作和像素级测量。因此，下文“代码确认”指源码直接支持的事实；布局溢出、视觉舒适度、DPI 效果仍需实机复验。没有声称当前页面已通过视觉验收。

### 已有能力，必须保留

- 连续 PDF 页面、页码跳转、适合宽度／整页／自定义缩放与 SyncTeX。
- 编辑优先、对照编辑、阅读优先，侧栏抽屉与布局保存。
- 文件树悬停操作、文档大纲、项目菜单、编译日志与错误定位。
- 弹窗的 Escape 关闭、基本焦点限制及关闭后焦点恢复。
- 保存冲突保护、编译取消、旧 PDF 保留与新产物提交机制。

不得将“重新实现以上能力”计入本次优化收益。

## 2. 具体不足与优先级

优先级：P1 为会影响核心任务的可用性问题；P2 为影响清晰度与一致性的问题；P3 为后续效率增强。本次没有依据认定存在需要立即停用应用的 P0 问题。

## 3. 目标页面与视觉规范

### 3.1 工作台布局

```text
┌ 项目菜单 · 当前项目             保存  [编译/取消]  布局  设置 ┐
│活动栏│ 文件树 / 搜索 │ 标签与编辑器          │ PDF 阅读工具栏 │
│      │              │                      │ 连续 PDF      │
│      │ 文档大纲     │                      │               │
│      │              ├ 问题 / 原始日志（按需展开）────────────┤
└ 保存状态 · 编译状态                       行列 · 编码       ┘
```

推荐顶栏 48px、面板标题和标签 36px、状态栏 26–28px；侧栏默认约 248–260px，保留拖拽。编辑和 PDF 比例继续使用现有偏好，首次进入采用 1:1，不覆盖用户已保存布局。

PDF 工具栏负责页码、缩放、适合宽度；编译生命周期属于全局工作台。关闭 PDF 不应影响编译能力。日志只在需要时占用空间，失败后显示问题摘要，不遮挡源码行与上一次成功 PDF。

### 3.2 色彩、字号与间距

以下是建议初值，并非已经过视觉测量的最终颜色：

| Token | 建议值／用途 |
|---|---|
| --surface-base | #1D232C，工作区底色 |
| --surface-raised | #252E39，弹窗与菜单 |
| --surface-subtle | #191F27，顶栏与活动栏 |
| --text-primary | #E0E7EF，主要正文 |
| --text-secondary | #B0BECC，辅助说明 |
| --text-muted | 另行实测确定，不能只靠降低透明度 |
| --accent | #8FBE9C，焦点与关键操作 |
| --border-subtle | #35414D，普通分隔 |
| --danger / --warning / --success | 独立语义色，搭配图标和文字，不能只靠颜色 |
| 间距 | 4、8、12、16、24px |
| 圆角 | 小控件 4px、菜单 6px、对话框 8px |
| 字号 | 主要 UI 13px、次级 12px、标题 16–18px、编辑器建议 14px |

优先提高重要文字清晰度，减少同时争夺注意力的边框和大面积绿色选中块。PDF 白纸必须保持真实页面色，不对文档本体套深色反转。Monaco 与外壳使用同一组语义色来源，但保留语法颜色辨识度。

内部验收目标：普通正文对比度至少 4.5:1，关键控件边界与焦点至少 3:1；这些是本项目拟采用的设计阈值，当前页面是否达到需逐项测量，不能仅凭截图下结论。

## 4. 按区域实施

### 顶栏与主操作

- 将编译／取消提升到 Header；同时显示编译模式的简短说明或菜单入口。
- 保存保留在顶栏；编辑器重复保存入口可移除，但保留 Ctrl+S。
- 建议新增 Ctrl+Enter 编译快捷键；实现前确认不与 Monaco、中文输入法冲突，不在组合输入期间触发。
- 打开项目保留菜单与首次使用空态，避免在顶栏过度重复。
- 编译禁用原因来自已有真实状态，例如“请先打开主文件”“正在切换项目”；不显示虚构成功状态。

### 资源管理器与标签

- 统一 30–32px 文件行、图标尺寸与缩进；选中、打开、未保存各有明确但不重复的标识。
- 悬停操作区域预留固定空间，长文件名不因悬停来回跳动。
- 目录操作优先绑定所选目录；保留相对路径高级输入，不要求普通重命名用户重新填写完整路径。
- 区分“项目为空”“筛选无结果”“读取失败”，分别提供新建、清空筛选、重试动作。
- 标签同名时显示最短可区分父目录；关闭按钮保留稳定槽位。

### 编辑区

- 保留 Monaco Model 生命周期、撤销栈与光标恢复，调整主题不能重建整个编辑会话。
- 编辑器字号作为独立设置，先提供有限范围，不与 PDF 缩放共用状态。
- 面包屑／路径只保留一处，可查看完整路径；不重复显示项目名与文件名。
- 粗体、斜体等低频 LaTeX 插入动作可收拢，保留撤销、重做、查找与源码定位。

### PDF 与编译反馈

- 保留连续滚动和按需渲染，页码随滚动更新；输入页码负责定位页面，不变回单页翻页。
- 分栏宽度变化时，适合宽度模式自动适配；手动缩放保留用户选择，允许有意的横向滚动。
- 运行中显示简洁进度文本与取消；失败时提示“显示上次成功结果”，避免旧 PDF 被误认作最新。
- 空态按无文档、未编译、编译中、工具链不可用、渲染失败分别设计；涉及底层恢复能力时先核对端口，不能做无效按钮。
- 不为视觉修改放宽 CSP、暴露文件系统或重写 PDF 字节缓存。

### 设置、对话框与诊断

- 通用 Dialog 提供标题、说明、正文、固定操作区；max-height 使用可用视口高度减边距，正文独立滚动。
- 设置拆为编译和编辑外观分组；超时对用户显示秒，提交时转换为原协议毫秒并校验范围。
- 移除主表单中的 SQLite／任意路径权限说明，放帮助或高级详情。
- 删除使用专门的危险操作样式与具体按钮文案；说明通过项目回收站恢复，不再引导手工搬文件。
- 诊断默认显示问题，原始日志单独切换；支持严重程度过滤、点击定位与复制，保留完整原始错误信息。
- 保存失败、冲突等需要行动的信息持续显示；普通成功提示不抢焦点、不自动遮挡编辑器。

## 5. 前端代码落地边界

建议逐步形成以下结构；新建目录不含连字符：

```text
frontend/web/src/
  shared/
    ui/                 Button、IconButton、Dialog、Field、EmptyState
    styles/             tokens.css、base.css
    ActionMenu.tsx      完善现有组件，避免平行造两个菜单
    Splitter.tsx
  app/
    layout/             Header、StatusBar、WorkbenchDialogs 与布局组合
    workflows/          保留现有保存／切换／冲突协调
  features/
    editor/             编辑与主题
    explorer/           文件树与操作
    preview/            PDF 阅读与编译展示
```

实施约束：

1. 通用 UI 不导入业务 Feature 或直接调用 RPC；Header 通过 props 接收状态与动作。
2. main.tsx 仍是组合层，先抽出 Dialog 组装与 StatusBar，避免一次大规模拆分掩盖 UI 回归。
3. 为 token 建立单一来源；每迁移一个组件删除相应旧选择器，不继续向末尾叠加覆盖。
4. 暂不引入新的大型 UI 框架或图标库；当前 SVG Icon 继续复用。
5. 外观偏好若只在当前前端生效，可用独立、有版本的本地偏好存储；若要求跨端统一，再单独设计协议和持久化迁移，不能悄悄加 RPC 字段。
6. 不修改 C++ 编译器调度、文档版本、取消语义和文件授权边界。

## 7. 验收矩阵与执行规则

### 尺寸与内容

- 桌面：1440×960 默认、1920×1080、1366×768、900×600 最小窗口。
- Windows 显示缩放：100%、125%、150%；记录屏幕尺寸、CSS 视口和实际缩放，不将三者混为一谈。
- 浏览器开发模式额外检查 760px 断点上下，不将 Fake 原生能力当成 Electron 验收。
- 内容：长中文项目名、同名文件、多层目录、20 个标签、长错误信息、多页 PDF、空项目。

### 核心验收场景

1. 仅键盘完成打开菜单、切换文件、调整布局、打开设置、提交／取消；关闭后焦点回到触发处。
2. 隐藏 PDF 后仍能手动编译和取消；按钮与状态栏信息一致。
3. 900×600 下设置底部按钮可达；错误变长时不会遮挡操作区。
4. 15 页以上 PDF 连续滚动，页码同步；跳到第 3 页、改变宽度、SyncTeX 后仍连续阅读。
5. 编译失败保留旧 PDF，并说明其不是最新结果；错误行可定位源码，后续成功更新提示。
6. 文件未保存、保存失败、外部冲突、项目切换忙碌状态有明确反馈且不丢编辑内容。
7. 对话框的输入、select、禁用控件及最后一个按钮分别验证 Tab／Shift+Tab；输入法组合期间不触发编译快捷键。
8. 全界面没有无意的横向滚动；PDF 自定义放大造成的滚动属于允许行为。
