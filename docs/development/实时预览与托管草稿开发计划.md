## 1. 已确认的用户行为

本计划以“只有导出时才要求目标路径”为核心约束。编译与导出是两个相互独立的用例，不再通过“先保存到用户目录”间接触发编译。

以下操作不得要求目标路径：

- 新建草稿、编辑、检查点和崩溃恢复。
- 草稿手动编译、停止输入后的实时编译、重新编译、取消和查看日志。
- 已打开本地项目的普通保存；它写回已授权 Workspace，不重复询问目录。

只有以下操作允许出现原生目录选择器：

- 打开已有项目时选择源目录。
- 用户显式执行“导出项目”或“另存为本地项目”时选择目标目录。

目录选择取消、导出失败或目标目录不合格不得改变当前草稿、当前 PDF 或编译状态，也不得被呈现为“编译失败”。

## 2. 目标用户流程

### 2.1 草稿实时预览

~~~text
Monaco Generation N
  -> 900 ms 停止输入防抖
  -> LiveCompileCoordinator
  -> build.previewStart(relative files + dirty overlay + generation)
  -> Compile Workflow
  -> 只读 Workspace 基础快照或空基础快照
  -> 合并不可变 Overlay Snapshot
  -> 内置 MiKTeX
  -> PDF/SyncTeX Artifact
  -> 仅当 generation 仍为最新且 PDF.js 加载成功时原子切换
~~~

新草稿使用应用管理的 Draft ID，不需要用户目录。Monaco Model 是未保存内容的唯一可修改事实来源；原生侧 Overlay 只服务一次编译 Generation，不能回写编辑器，也不代表已导出。

### 2.2 导出项目

~~~text
用户点击“导出项目”或“另存为”
  -> Qt 原生目录选择器
  -> 原生侧生成短期、会话绑定的一次性 destinationToken
  -> React 仅收到 token 与安全显示名
  -> Export Application 校验目标目录
  -> 逐文件原子非覆盖写入
  -> 返回完整成功或结构化 Partial Export 报告
  -> 用户明确选择后才切换为已导出的本地项目
~~~

绝对路径不得进入 React 或通用 RPC DTO。目标路径保留在原生授权注册表中，destinationToken 必须具备会话绑定、用途绑定、过期时间和单次消费语义；取消导出或会话结束时立即失效。

## 3. 模块与职责

| 模块 | 责任 | 明确禁止 |
| --- | --- | --- |
| Editor Feature | 管理 Monaco Model、Dirty Buffer、Generation 与用户命令 | 操作本地路径、启动 TeX、保存第二份可编辑正文 |
| LivePreview Workflow | 原生侧权威管理 Latest-wins、取消、Pending 与过期结果丢弃；前端只发防抖后的意图 | 读取绝对路径、解析 TeX 日志、持有 MiKTeX 类型 |
| Compile Workflow | 校验请求并编排 Snapshot、Compiler、Artifact 端口 | 选择导出目录、依赖 React/Qt/CEF |
| Build Snapshot Store | 读取基础快照并合并不可变 Overlay | 修改 Workspace 或草稿正文 |
| Export Application | 校验授权、导出策略、原子非覆盖写入与部分失败报告 | 启动编译、调用 Build Adapter |
| Qt Export Adapter | 显示目录选择器并创建原生授权令牌 | 决定业务导出规则或读取 Monaco |
| Preview Feature | PDF.js 加载、保留旧 PDF、提交新 Artifact 与错误展示 | 访问绝对路径、解析本地 PDF 文件路径 |

依赖方向保持 domain <- application <- adapters/platform <- composition root。Adapter 之间不得互相调用；Compile 与 Export 只能由上层应用组合协调。

### 3.1 目标目录与 CMake Target

在不搬动既有模块的前提下，新增两个边界清晰的业务模块，并只扩展 Build 的现有端口：

~~~text
src/modules/
├── draft/
│   ├── domain/                  # Draft ID、Generation、Checkpoint 元数据
│   ├── application/             # lol_draft_inbound/outbound/app
│   └── adapters/sqlite/         # lol_draft_adapter_sqlite，仅保存检查点
├── build/
│   ├── domain/                  # 扩展 Overlay 与 Snapshot 合并规则
│   ├── application/             # 现有 lol_build_inbound/outbound/app
│   └── adapters/windows/        # 现有 MiKTeX 进程与临时快照实现
├── export/
│   ├── domain/                  # 目标策略、Export Result、Partial Export
│   ├── application/             # lol_export_inbound/outbound/app
│   └── adapters/localfs/        # lol_export_adapter_localfs
└── preview/                     # 保持既有 Artifact 服务边界

src/orchestration/
└── livepreviewworkflow/
    ├── include/                 # IKLivePreviewWorkflow
    └── src/                     # lol_livepreviewworkflow_app，编排 Draft/Workspace/Build/Preview Inbound

backend/latexlocalservice/app/platform/qt/                # 目录选择与授权令牌注册，不含导出业务
src/bridge/                     # Schema 校验、DTO 转换、事件与取消
backend/latexlocalservice/app/composition/                   # 唯一组合根，只注入端口并管理生命周期
frontend/web/src/
├── app/                         # 跨 Feature 组合与 900 ms 输入防抖
├── features/editor/             # Monaco、Dirty Overlay、Generation
├── features/preview/            # PDF 双缓冲和日志呈现
├── features/export/             # 导出命令与结果 UI
└── native-api/                  # 生成契约，不含原生路径实现
~~~

Target 依赖限定如下：

- lol_draft_domain 只依赖标准库；lol_draft_app 只依赖 Draft Domain 与 Draft Ports。
- lol_build_app 只接受调用者提供的基础 Snapshot 标识与 Overlay，不链接 lol_draft_app、lol_workspace_app 或它们的 Adapter。
- lol_livepreviewworkflow_app 只依赖 Draft、Workspace、Build、Preview 的 Inbound Port，权威持有活动 Job、Pending Generation 和取消状态；它不依赖具体 Adapter、Qt、CEF 或 React。
- lol_export_app 只依赖 Export Domain 与 Export Ports。目录选择通过 IKExportDestinationPicker Outbound Port 调用 Qt 实现，不链接 lol_build_app 或 lol_preview_app。
- lol_composition 是唯一允许同时看见具体 Draft、Build、Export、Preview Adapter 的 Target，但只负责注入端口和生命周期，不保存编译调度业务状态。
- 前端 features/editor、features/preview、features/export 互不导入内部文件；frontend/web/src/app 只做 900 ms 防抖和公共接口组合，原生 Workflow 仍是并发与 Generation 接受规则的事实来源。

## 4. 契约草案

建议在现有 RPC Schema 中新增或演进以下方法；最终字段必须由单一 Schema 生成 C++ 与 TypeScript 类型：

- build.previewStart：提交 draftId/projectId、mainFileId、generation、基础 Revision 和 Dirty Overlay。
- build.previewCancel：按 jobId 或 generation 协作取消。
- draft.checkpoint / draft.restore：管理应用内部草稿，不带用户目标路径。
- export.selectDestination：打开原生选择器，返回 destinationToken、displayName 和 expiresAt。
- export.project：消费 destinationToken 与指定 Draft/Project Generation，执行导出。

Overlay 文件只允许规范化的相对 File ID，并携带内容、编码和可选基础 Revision。RPC、Application、Snapshot Adapter 都要验证：文件数量、单文件字节数、总字节数、重复路径、空主文件、路径穿越、绝对路径和非法 UTF-8。

编译失败统一包含稳定 code、phase、jobId、generation 和有界 diagnostics。phase 至少区分 snapshot、detect、compile、artifact、render，使界面能准确说明失败发生在快照、工具链、TeX、产物还是 PDF.js，而不是只显示“编译失败”。

## 5. 实时调度与状态机

设置从布尔 autoCompile 迁移为三态：

- manual：仅用户点击编译。
- onSave：成功保存或草稿检查点后编译。
- live：停止输入 900 ms 后编译；新安装且没有旧设置的用户默认此模式。

已有 autoCompile=true 迁移为 onSave，false 迁移为 manual，迁移必须幂等并有 Fixture。

调度规则：

1. 编辑输入仅更新 Monaco 和 generation；不直接启动进程。
2. 100 ms 内的连续 UI 更新合并渲染，编译使用 900 ms 停止输入防抖。
3. 同一草稿或项目最多一个活动 Job 和一个合并后的最新待处理 Generation。
4. 新 Generation 到达时请求取消旧 Job；若底层暂未结束，只保留最新一个 Pending。
5. 手动编译跳过防抖，但仍遵守单活动 Job 和 Generation 校验。
6. 任意旧 Generation 的日志、诊断、进度和 Artifact 都不能覆盖较新状态。
7. 新编译进行中、失败或取消时继续显示上一份成功 PDF，并标识“预览来自 Generation X”。
8. 只有完整 Artifact 校验成功且 PDF.js 完成加载后，才原子提交新 PDF；render 失败仍保留旧 PDF。
9. TeX 能力探测按 Runtime 指纹缓存；Runtime 目录、清单或设置变化才重新探测，不在每次按键后遍历目录。

验收：前后端契约 Fixture 一致；旧设置迁移幂等；RPC 中不存在绝对路径字段。

### M9.1 Overlay Snapshot

- 扩展 Build Snapshot 端口，支持“只读基础快照 + Overlay”。
- 新草稿使用空基础快照，已有项目使用已授权 Workspace 的固定 Revision。
- 对冲突 Revision、重复 File ID、越界内容、取消与清理增加 Domain/Application/Adapter 测试。

验收：切换 Fake/Windows Snapshot Store 不改变 Use Case；编译准备不修改用户文件或 Draft Store。

### M9.2 草稿直接编译

- 将当前“保存并编译”拆为独立“编译”和“导出”命令。
- 草稿手动编译直接发送 Overlay，不再调用 openWorkspace 或目录选择器。
- 编译失败保留结构化日志和现有成功 PDF。

验收：全新草稿不创建用户目录、不弹路径窗口，也能通过 Fake 与内置 MiKTeX 生成 Artifact。

### M9.3 Latest-wins 实时调度

- 实现 900 ms 防抖、单活动加单 Pending、协作取消和过期结果丢弃。
- 覆盖快速输入、连续保存、手动抢占、取消迟到、Renderer 恢复和应用退出。

验收：压力 Fixture 中最终 PDF 必须对应最后 Generation；没有并行 TeX 风暴、僵尸进程或退出悬挂。

### M9.4 预览连续性与诊断

- PDF.js 采用加载成功后提交的双缓冲语义。
- 日志页展示 phase、首条可操作诊断、完整有界日志与“继续显示旧预览”状态。
- 提供重新编译、取消和跳转诊断入口。

验收：compile/artifact/render 分别失败时旧 PDF 不消失，错误不会误导为导出或目录问题。

### M9.5 独立导出用例

- 建立 Export Application、目标授权端口和 Local Filesystem Adapter。
- Qt 只负责目录选择和 destinationToken 注册；React 不接触绝对路径。
- 新建或空目录校验、原子非覆盖写入、Partial Export、令牌过期和重复消费全部测试。

验收：编译链路不链接 Export Adapter；取消导出不改变草稿、项目或预览；正常项目保存不重复选目录。

### M9.6 发布级验收

- 运行前端测试、契约测试、Debug/Release CTest、架构检查与 Full 绿色目录 smoke。

## 8. 性能与资源预算

以下是需要实测的目标，不是当前已达成结论：

- 输入到调度：停止输入后 900 ms 触发，额外 UI 调度延迟 P95 小于 100 ms。
- 小型文档首次预览：内置 Runtime 热启动 P95 目标小于 3 秒；大型项目单独记录，不混合统计。
- 同一会话并发 TeX 进程：最多 1 个；Pending Generation 最多 1 个。
- Overlay：沿用 RPC 总容量上限；超过上限时明确提示用户手动保存/拆分，不能截断正文后继续编译。
- Artifact/草稿缓存：沿用既有容量治理，并增加按 Draft ID、最后访问时间和活动 Job 的安全清理。

每次性能记录必须包含设备、Release 构建、文档 Fixture、Runtime 清单、冷/热启动和测量方法。

## 9. 完成定义

M9 只有同时满足以下条件才可标记完成：

1. 新草稿手动与 live 编译均不请求目标路径。
2. 只有显式导出/另存为请求目标目录；打开项目的源目录选择被清楚区分。
3. Monaco、Draft Checkpoint、Overlay Snapshot、Workspace 与 Export 的数据所有权没有重叠。
4. Latest-wins、取消、超时、旧结果丢弃和进程释放均有自动化证据。
5. 编译失败不会清空最后成功 PDF，render 成功前不会提交新 Artifact。
6. React/RPC 不接收绝对路径，导出令牌不可跨会话、跨用途或重复使用。
7. Build、Export、Preview、Qt 与 MiKTeX Adapter 可独立替换且无 Adapter 互调。
8. 相关构建、测试、真实 MiKTeX 和 Full 目录验收通过并记录。
9. 文档与实现一致；当前未完成项不得被描述为已交付。
