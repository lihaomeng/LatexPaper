# 架构拆分与开发构建解耦

## 决策

保留 Qt/CEF + React + C++ 技术栈。本轮不引入 Electron，不重写原生业务模块，不新增通用事件总线。先抽离独立职责，以现有行为为基线渐进替换。

## 分阶段范围

| 阶段 | 范围 | 状态 |
|---|---|---|
| A | 原生服务装配、编译 RPC 控制器、目标项目编辑会话准备 | 已接入，最终 dev 构建通过；交互待验收 |
| B | 开发依赖安装与 Runtime 部署增量化 | 首次部署及缓存复用通过；最终构建使用 FreshConfigure |
| C | Workspace/Document/Session Controller 与统一切换状态机 | 待实施；工作台仍持有这些状态 |
| D | 项目级主文档与独立会话、PDF 阅读位置、日志分级 UI | 待实施；本轮只保留诊断 severity |
| E | WorkbenchView 纯展示化、桌面人工验收、发布文档统一 | 待实施 |

## 已抽出的边界

- `nativeServices.ts`：集中创建 NativeApi 客户端及超时配置，Feature 不直接装配 CEF。
- `compileController.ts`：以窄接口注入原生 API，管理请求、Generation、日志轮询、取消、过期响应和 PDF 候选发布；不依赖 React Hook 或 Monaco。
- `prepareWorkspaceSession.ts`：根据项目快照和已保存会话准备编辑模型，失败释放新模型，不修改当前显示会话。
- Workbench 仍协调切换和显示；手动、live、onSave 都经过同一个受保护编译入口。后续按状态所有权拆除剩余大组件，不仅移动 JSX。

- `PdfCanvas.tsx` 与 `model.ts`：分离 PDF 渲染生命周期、状态模型及预览面板展示，保留高 DPI 逻辑。

## 开发构建

继续使用 `scripts/build.ps1 --dev`，不执行测试目标。

- 前端 package.json、package-lock.json 和 Node 版本不变、依赖存在时跳过 npm ci；TypeScript、协议生成和 Vite 构建仍每次执行。
- Runtime 首次部署后记录开发指纹。源目录路径、文件清单/大小/时间戳或部署脚本变化时重新部署；关键目标工具或格式文件丢失时重新部署。
- 开发指纹不是完整内容完整性证明；源文件同大小同时间戳的替换、目标非关键宏包损坏仍需显式刷新。
- 强制修复：`scripts/build.ps1 --dev -RefreshRuntime`。
- 非 dev 构建仍 npm ci + check，并完整执行 Runtime 部署，发布规则不降低。
- 新增脚本不删除源 Runtime、不打包归档，不启用联网宏包下载。

## 验收边界

构建通过不能替代项目切换、取消编译或退出恢复的人工验收；C～E 阶段未完成，不宣称全部架构拆分完成。保留先前 PDF 高 DPI 修复及其他用户变更。

## 本机配置恢复

本机重复 CMake Configure 存在进程异常退出，尚未定位根因。显式运行 `scripts/build.ps1 --dev -FreshConfigure` 已通过最终构建；该选项重置配置缓存到预设默认值，不会在普通 dev 构建中自动启用。自定义缓存选项应先备份。详见 ../acceptance/2026-09-17-架构拆分与开发构建.md。
