# 项目切换与启动恢复

## 问题与变更

- 原目录选择 RPC 前后端均为 5 秒超时，选目录时间也计入；现在项目打开/重开原生预算为 300 秒，前端等待 305 秒。其他普通文件请求仍保持短超时。
- 原历史只有项目 ID，无法重开。新增 Session 端口及 SQLite `workspace_locations` 表，保存原生选择器授权的 ID 到目录映射；`workspace.reopen` 只接受 ID，不接受任意路径。
- 启动先读取会话，再恢复上次项目及标签、位置、布局；恢复结束前不写空会话。目录不存在或旧版记录没有映射时，提示重新选择。
- 顶栏“最近项目 / 切换”和设置中的历史按钮可以重新打开项目；名称缓存仅用于显示，路径和授权映射仍在原生 SQLite。
- 切换期间禁止编辑和重复切换；未保存本地修改、保存冲突或文件操作未结束时阻止切换。草稿仍由独立草稿会话持有。
- 取消旧编译并隔离过期响应；新项目加载后重置过滤、搜索和 PDF。打开失败时核对原生状态，避免继续显示失效项目。
- 项目工作流先准备文档、搜索和编译服务，再提交项目；同目录重开不会误关闭新文件监视器。

## 验证范围

- 按用户要求仅运行 `scripts/build.ps1 --dev`，不运行 CTest、npm test 或测试编译目标。
- 新增重开请求契约正反例，更新 Fake Session 以匹配新增端口；这些测试未执行。
- 首轮开发构建已通过 C++、TypeScript、Vite 与内置 Runtime 部署；最终复查后再次构建也通过（退出码 0），167 个 V2 契约样例参与代码生成，架构检查 66 个 Target 通过。
- 尚未进行桌面人工点击验收；编译通过不等于以下交互均已实测。

## 人工验收

1. 启动 `out/desktop-release/bin/Release/LightOverLeaf.exe`，打开 `paper1`，在选择器停留超过 5 秒再确认，检查文件树、项目名和 main.tex 更新。
2. 打开另一个含不同文件的项目，通过“最近项目 / 切换”往返切换，确认文件和预览不串项目。
3. 保存修改后，等待会话保存（约 500 毫秒），关闭并重启，检查上次项目、标签和位置恢复。
4. 未保存修改时尝试切换，应提示先保存；取消目录选择应保留原项目。
5. 重开同一目录后外部增删文件，检查刷新；移动最近项目目录后点击记录，应提示重新选择。

## 兼容性

旧 SQLite 表不删除，只新增映射表；旧项目记录需要手动选择一次才能获得路径映射。当前恢复保存的是上次活动项目会话，不是每个历史项目独立的完整标签快照。
