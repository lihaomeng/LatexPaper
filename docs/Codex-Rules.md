# Codex 全局规则

这些规则适用于当前用户的 Codex 会话；如果具体项目中存在更具体的 `AGENTS.md` 或更高优先级指令，则以更具体、优先级更高的规则为准。

# C++ / Qt K 风格质量规范

对所有新增或修改的 C/C++、Qt、插件和构建代码执行本规范。把外部输入视为不可信数据，并优先保证正确性、安全性、生命周期清晰和跨平台行为。

## 规则层级与使用流程

1. 先读取当前仓库适用的 `AGENTS.md`、项目格式化配置、平台抽象层和既有公共接口。
2. 按“更具体的项目规则 > 本全局规则”的顺序处理差异；本全局规则内以安全硬规则和 K 命名规则为基线。
3. 先确认数据所有权、线程归属、输入边界、错误语义和目标平台，再修改代码。
4. 只修改任务范围内的代码；不要顺手大规模格式化或重命名无关文件。
5. 完成后执行与风险相称的编译、静态检查和测试，并区分“实际执行”“静态检查”“人工验收待办”。

## 提交前检查清单

- [ ] 类型使用 `K` 前缀，纯抽象接口使用 `IK` 前缀。
- [ ] 成员使用 `m_` + camelCase；方法、局部变量和参数使用 camelCase。
- [ ] 同一访问级别的成员函数和成员变量分区，并分别重复书写访问说明符。
- [ ] 自有 C/C++ 文件全小写、无下划线和连字符，并与主类型对应。
- [ ] 多语句块使用 Allman；`catch` 必须有大括号。
- [ ] 指针、句柄、描述符、`BOOL` 和数值成员均已初始化。
- [ ] 资源所有权唯一清晰；释放后按规则立即置为无效值。
- [ ] 公共 API、外部输入、数组长度、整数运算和下标均已做运行时校验。
- [ ] 缓冲区操作显式携带容量并检查安全函数返回值。
- [ ] 未引入命令、路径、SQL、格式串、动态库或配置注入。
- [ ] Qt 父子所有权、异步回调和 GUI 线程规则正确。
- [ ] DPI、编码、国际化、路径和定宽类型满足目标平台要求。
- [ ] 失败路径有返回值、日志或埋点；没有调试残留和敏感信息。
- [ ] 头文件、构建资源、插件 host 和导出路径与实际目标一致。
- [ ] 已编译或执行相关检查；未执行的验证明确标注。

## 1. K 风格命名与文件

| 类别 | 规则 | 示例 |
|---|---|---|
| class / struct / enum / alias | `K` + PascalCase | `KCommandRouter`, `KUnit` |
| 纯抽象接口 | `IK` + PascalCase | `IKLineHandler` |
| 非静态成员 | `m_` + camelCase | `m_isError`, `m_fromUnit` |
| 方法 / 自由函数 | camelCase | `registerUnit`, `buildHelp` |
| 局部变量 / 参数 | camelCase，无 `m_` | `line`, `categoryId` |
| 自有文件 | 全小写、无 `_`/`-` | `kcommandrouter.h/.cpp` |

不要引入 `CommandRouter`、`ILineHandler`、`m_snake_case`、`build_help()` 或 `command_router.cpp`。入口文件可保留 `main.cpp`；不强制修改 STL、第三方类型、已有命名空间或可执行目标名。

重命名类型时同步重命名文件，更新全部 `#include`、前置声明、构建清单、导出配置和测试引用。同一次改动不要混用新旧命名。

使用能表达业务含义的名称。不要依赖按钮可见文本、翻译文案或字符串字典序识别功能；使用稳定的 enum、ID 或 property。

### 成员函数与成员变量必须分区

同一访问级别下，成员函数和成员变量必须放在不同区段，并分别重复书写 `public:`、`protected:` 或 `private:`。禁止让成员函数和成员变量共用同一个访问说明符。只有相应类别不存在时才省略该区段。

```cpp
private:
    void close();

private:
    HKEY m_key = nullptr;
};
```

## 2. 格式、头文件与常量

多语句块使用 Allman：

```cpp
if (condition)
{
    statementOne();
    statementTwo();
}
```

单语句控制流可省略大括号；`catch` 必须保留大括号：

```cpp
if (result.m_isError)
    return false;

try
{
    value = thirdPartyParse(text);
}
catch (...)
{
    return false;
}
```

- 使用项目既有缩进配置；没有项目规则时保持文件现有风格，不在功能改动中制造全文件空白差异。
- 用空行表达逻辑分组，删除无意义的连续空行、注释掉的旧代码和临时调试代码。
- 头文件优先前置声明，减少不必要的 include；只在需要完整类型时包含头文件。
- 头文件使用 `#pragma once`，除非项目明确要求传统 include guard。
- 预编译头只包含稳定依赖，并按项目构建规则放在 `.cpp` 的规定位置。
- 编译期常量使用 `constexpr`；为魔法数字、特殊字符、固定边界和业务状态命名。
- 不要为常量创建具有动态初始化的全局对象；优先局部值、`constexpr` 或函数内静态值。
- 仅在类型从右值一目了然或迭代器等场景使用 `auto`；当类型影响语义、单位、所有权或错误判断时显式声明。
- 非平凡只读参数优先使用 `const T&`，但小型标量和值语义类型按值传递。
- 让翻译资源只包含国际化内容，不夹带业务代码或无关配置。

## 3. 初始化、API 与错误流

- 声明指针、资源句柄、文件描述符、套接字和 `BOOL` 时立即初始化为 `nullptr`、无效句柄、`-1`、`INVALID_SOCKET` 或 `FALSE`。
- 在类内初始化器或构造函数中初始化所有成员；整数和状态成员也必须有明确初值。
- 构造函数不要执行可能失败的业务操作，不建议创建线程；有资源成员时提供明确析构或使用 RAII。
- 公共 API 参数必须做运行时检查并返回错误；不要用断言替代输入校验。
- 只使用项目 Debug 断言宏，不直接调用 `assert()`。断言中禁止赋值、递增、释放资源或其他副作用；一条断言只检查一个内部不变量。
- 用返回值、错误码或结果对象传递业务错误；不要使用 C++ 异常作为常规业务错误流。
- 接管 STL、内存分配或第三方异常时，在合适边界捕获并转换为项目错误语义。
- 函数声明、定义和实际返回语义必须一致；不要把 `bool` 当 `HRESULT` 或反向混用。
- 失败分支必须完整：检查被调用函数返回值，再检查输出对象；必要时记录日志、埋点或展示可恢复的占位状态。
- 不在非入口函数调用 `exit`/`ExitProcess`，不使用 `atexit`、`setjmp`/`longjmp`，不随意 `abort`、`kill`、`TerminateProcess`、`pthread_exit` 或 `ExitThread`。
- 禁止 `delete this`。

## 4. 外部输入、整数与缓冲区安全

把文件、网络、IPC、插件、COM、命令行、环境变量、配置、用户输入和持久化数据都视为不可信。

- 可写数组或缓冲区参数必须同时传入容量；只读、保证以 `\0` 结尾的 C 字符串可按接口约定处理。
- 使用指针前判空；只有内部且已证明非空的不变量才可使用断言，公共 API 仍需运行时校验。
- 外部值用作长度、容量、下标、循环次数、偏移、枚举或分配大小前，检查上下界和类型转换。
- 检查加减乘的溢出、符号反转、除零、截断和扩宽时机；先转为足够宽的类型再计算。
- 优先 `int32_t`、`uint64_t`、`qint64` 等定宽类型；避免依赖 `long`、`ushort` 等平台宽度。
- 有符号整数避免位运算；指针与整数转换使用 `uintptr_t`。
- `char` 用作数组下标前转为 `unsigned char`。
- 不用空指针构造 `std::string`；保证输出缓冲区容量足够且正确终止。
- 禁止用指针的 `sizeof` 推断数组长度；显式传递 `size` 或 `count`。
- 禁止 `realloc` 和 `alloca`。分配前检查非零且合理的大小，分配后检查结果并在使用前初始化。
- 禁止无界或危险的 `memcpy`、`memmove`、`memset`、`strcpy`、`strncpy`、`strcat`、`sprintf`、`gets` 等调用。使用项目认可的安全 API，传入目标容量并检查其返回值。
- 不要封装安全函数后丢弃 `destMax`，也不要用宏伪装危险函数。
- 格式串必须由程序控制，参数类型和数量必须匹配；外部文本只作为 `%s` 等数据参数。
- 循环必须有明确退出条件；受外部输入控制的循环必须设置合理上限。

## 5. 资源、所有权与生命周期

- 优先栈对象、RAII、智能指针和容器值语义；每个资源只设一个明确所有者。
- 释放原始指针、句柄或描述符后立即置为 `nullptr` 或无效值；若释放是作用域最后一句可省略。
- 不让两个原始指针容器共同拥有同一批对象；观察关系使用非 owning 指针、弱引用或稳定 ID。
- 不在旧对象仍存活时用新指针覆盖成员；先复用、关闭或按所有权规则销毁旧对象。
- 返回私有数据的公共接口优先返回 const 视图或副本，避免暴露可修改内部指针。
- 动态库、文件、COM 接口、套接字、锁和线程句柄都必须覆盖成功与失败路径的释放。
- 不在锁仍被持有时销毁 mutex；共享状态使用正确同步，优先 `lock_guard` 等 RAII 锁。
- 单例初始化必须线程安全，并慎用单例；退出时确保引用方不会保留悬空地址。

### Qt 所有权

- 给堆上创建的 `QObject` 设置正确 parent，或用明确智能指针管理；不要同时使用 parent 所有权和重复手动 `delete`。
- Qt 父对象会销毁子对象；析构函数不要再次删除已归 parent 管理的对象。
- 无需堆分配的短生命周期对象放在栈上。
- 独立顶层窗口按需求设置 `Qt::WA_DeleteOnClose`，并使用 `QPointer` 观察其生命周期。
- 异步回调、`singleShot` 和 queued connection 不捕获可能先销毁的裸 `QObject*`；使用 `QPointer`、受控 context object 或其他弱引用方案。
- 只有确认容器唯一拥有对象时才使用 `qDeleteAll`；否则先修正所有权模型。
- 修改容器时遵守迭代器失效规则；不要把“改成下标遍历”当作通用修复。

## 6. 逻辑与状态一致性

- 逐项核对空/非空条件、早退条件、取反、边界符号和分支顺序，特别关注“为空才创建”类逻辑。
- 在访问块、数组、字符串或游标前同时检查负值和上界。
- 除法前检查除数；浮点数按业务容差判断，整数直接判断零。
- 字符识别先检查长度，再调用字符 API，如 `QString::at(0).isDigit()`；不要用字符串字典序替代字符范围判断。
- `switch` 必须显式处理意外值，或在穷尽 enum 且有编译器检查时记录该设计；不要静默吞掉未知状态。
- 为一份业务状态建立单一事实来源；模式切换时不要维护可能分叉的重复副本。
- 静态容器只初始化一次；不要在每次调用时重复追加。
- 没有自定义析构逻辑时使用 `= default`；基类析构为 virtual 时在派生析构上使用 `override`。
- 将成员和方法设置为满足需求的最小访问级别，默认不暴露实现细节。

## 7. Qt 线程、GUI、DPI 与跨平台

- 只在 GUI 线程访问 `QWidget`、`QPixmap` 和界面状态。工作线程处理数据时使用 `QImage` 等合适类型，再通过 queued signal/invoke 回到 GUI 线程提交结果。
- 不把“给 `QPixmap` 加锁”视为跨线程安全方案。
- 主线程退出前请求工作线程停止并完成 join/wait；等待协议必须有明确状态、退出条件和必要的超时策略。
- 跨线程共享状态使用 mutex、原子类型或消息传递；不要依赖非原子读写的偶然时序。
- 异步数据尚未就绪时提供明确状态，不能只靠一次判空掩盖竞态。
- UI 尺寸、边距、图标和坐标使用项目 DPI 抽象或布局系统；避免未经缩放的硬编码像素。
- Qt 5 的高 DPI 属性按项目启动顺序和版本要求配置；Qt 6 优先依赖其默认高 DPI 行为，不照搬旧版开关。
- 使用 `QStandardPaths`、`QDir`、`std::filesystem` 或项目平台层处理路径；不要直接依赖 `APPDATA`、`HOME` 或平台分隔符。
- 动态库导出使用项目跨平台宏，不在公共头中散落裸 `__declspec`。
- 源码、配置和翻译文件保持项目要求的 UTF-8 编码。只有源字节确为 Latin-1/ASCII 时才使用 `fromLatin1`/`QLatin1String`；不能为性能错误解码 UTF-8。
- 跨平台核心逻辑、公共接口、插件 ABI、持久化格式、网络和 IPC 协议不得使用 `wchar_t` 或 `std::wstring` 作为通用文本表示；`sizeof(wchar_t)` 由平台决定，Windows 通常为 2 字节，Linux 通常为 4 字节，不能假设其二进制布局兼容。
- 仅在调用必须使用宽字符的 Windows API 时，于平台适配边界使用 `wchar_t` / `std::wstring`，并在进入或离开该边界时显式转换；不得让宽字符类型渗透到跨平台业务模型和协议中。
- 跨平台文本默认使用 UTF-8 的 `char` / `std::string`；协议确实需要固定宽度码元时，根据协议显式使用 `char8_t`、`char16_t` 或 `char32_t` 及其对应字符串类型，并明确编码、字节序和转换规则。
- 不得把 `sizeof`、字符串容器的 `size()` 或 UTF-8/UTF-16/UTF-32 码元数量直接当作 Unicode 字符数或用户感知字符数。界面长度、截断、光标移动和字符限制应按需求使用 Unicode 标量值或字素簇边界计算。

## 8. 注入、敏感数据与文件安全

- 禁止将外部数据直接传给 `system`、`popen`、`CreateProcess`、`LoadLibrary`、`dlopen` 等接口。
- 禁止通过字符串拼接构造带外部输入的 SQL；使用参数化查询。
- 外部路径先规范化，再校验是否仍位于允许根目录；防止 `..`、符号链接、盘符和 UNC 绕过。
- 创建包含私有数据的文件时显式设置合适权限；不要把私有临时文件放在共享临时目录。
- URL、域名和环境端点通过受控配置或项目 domain 接口管理。不要把“拆分字符串”或“可逆加密硬编码”当成安全措施。
- 不提交密钥、口令、令牌、私钥或真实环境配置。敏感缓冲区用完后使用 `memset_s`、`SecureZeroMemory` 等可靠方式清零。
- 不用 `std::string` 长期保存口令或密钥；安全用途禁止使用 `rand()`。
- 信号处理函数只调用异步信号安全函数。

## 9. 性能、可维护性与设计

- 先保证正确性，再根据测量结果优化；不要把微优化经验写成无条件替换。
- 默认优先连续存储容器，如 `std::vector`；已知元素数量时调用 `reserve()`。只有访问和修改模式确实适合时选择 `list`。
- 大文件或大响应使用流式读取，避免无界一次性加载；同时设置输入大小上限。
- 优先事件驱动；使用定时器时明确频率、停止条件、对象生命周期和后台耗电影响。
- 合并真正重复的流程，但不要为了少几行代码制造难懂抽象。
- 删除未使用 include、重复赋值和无关依赖，降低编译和运行成本。
- 复杂 lambda、深层嵌套或承担多项职责的函数应拆成可命名、可测试的单元。
- 无状态工具函数优先放在合适命名空间；只有存在状态、不变量或多态需求时设计类。
- 接口遵循单一职责；扩展优先通过稳定抽象或组合完成，不为猜测中的未来需求过度设计。
- 使用设计模式必须能说明它解决的具体问题；单例不是默认选择。
- 日志使用项目日志模块和结构化字段，不手工重复拼接上下文。

## 10. 插件、构建与发布配置

- 插件加载失败必须记录可定位的错误信息或埋点，同时避免泄露敏感路径和数据。
- 检查插件配置是否在实际发布模式生效，不要只验证 Debug。
- 检查 CMake/项目文件中的源文件、资源导出路径、目标库目录和安装规则是否指向真实产物。
- 检查插件应由主框还是非主框加载，以及 host 进程是否与目标组件匹配；不要机械复制示例中的 `wpsoffice`、`wpp` 等值。
- 动态加载只使用受信任、规范化、白名单内的库路径，并在卸载前停止所有使用该库代码或对象的任务。

## 11. 审查与验证输出

审查时按严重程度优先报告：

1. 安全漏洞、未定义行为、崩溃、数据损坏和线程竞态。
2. 错误结果、状态不一致、资源泄漏和平台不兼容。
3. 性能退化、可维护性、命名和格式问题。

每条发现都要给出：

- 精确文件与位置；
- 可触发条件和实际影响；
- 对应规则；
- 最小可行修复；
- 证据边界：已复现、已编译验证、静态推断或需人工确认。

不要把猜测写成已确认缺陷。不要因为“存在代码”就声称功能已工作，也不要因为静态检查通过就声称运行时验收完成。

## 快速正误对照

```text
CommandRouter       -> KCommandRouter
ILineHandler        -> IKLineHandler
bool isError        -> bool m_isError
void build_help()   -> void buildHelp()
CommandRouter.h     -> kcommandrouter.h
char *p;            -> char *p = nullptr;
printf(userText)    -> printf("%s", userText);
throw KBusinessErr  -> return KResult / error code
button->text() 分派 -> stable enum / ID / property
裸 QObject* 异步捕获 -> QPointer / context-bound callback
外部字符串拼 SQL   -> parameterized query
```
