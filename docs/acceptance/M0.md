# M0 实施与验收记录

日期：2026-09-11。范围依据开发要求第 24 节：架构骨架、契约生成、空 React 应用和最小 Qt/CEF 启动验证。

## 实际交付

- 初始化 Git 与忽略规则；未自动创建提交，保留原有需求与规则文件。
- C++20、显式 CMake Source/Target、Debug/Release 和纯核心/桌面四种 Preset。
- Kernel，System/Workspace/Document 各自的 Domain、Inbound、Outbound、App；RPC Core、CEF Transport、Platform、Composition 骨架。业务 Target 仍为空骨架。
- 从真实 CMake Target 的链接属性导出图；Configure 拒绝未知元数据、宽泛 Include 根、越层依赖与循环；扫描核心源码中的框架泄漏。
- 5 个非法依赖图样例，以及独立临时工程中真实的 Domain → Qt 链接失败测试。
- 单一 Ping Envelope Schema 生成 C++ DTO/验证器/方法常量及 TypeScript DTO/验证器/NativeApi 基础接口；生成代码忽略并检查漂移。
- 两种语言共享 23 个接受/拒绝 Fixture，涵盖字段缺失、额外字段、错误版本/方法、类型、ID 字符与长度、数值边界。
- React/Vite 空应用、显式 Fake NativeApi、合法与非法 Feature 导入测试。
- CEF 发行版 Bootstrap、Qt Shell、受控离线资源加载、CSP、Sandbox、Qt 间接 DLL 自动解析与部署。
- 自动启动测试等待 React 就绪标题，再关闭浏览器并退出应用；正常路径先 OnBeforeClose，后 CefShutdown。

## 执行命令与结果

在仓库根执行：

```powershell
cmake --fresh --preset core-debug
cmake --build --preset core-debug
ctest --preset core-debug
cmake --fresh --preset core-release
cmake --build --preset core-release
ctest --preset core-release

cmake --preset desktop-debug
cmake --build --preset desktop-debug
ctest --preset desktop-debug
cmake --preset desktop-release
cmake --build --preset desktop-release
ctest --preset desktop-release

npm.cmd run check --prefix web
```

| 验证 | 结果 |
|---|---|
| Core Debug / Release | 各 4/4 CTest 通过 |
| Desktop Debug / Release | 各 5/5 CTest 通过，包含实际 Bootstrap 启动、React 就绪和退出 |
| Frontend | ESLint、26 项测试、TypeScript 检查、Vite 生产构建通过 |
| 禁用桌面模块 | 不查找或链接 Qt/CEF，独立配置、构建与测试通过 |
| Codegen | CMake/npm 自动生成；C++/TS 生成结果漂移检查通过 |

本次修复并复验的问题包括 Schema 元数据 TypeScript 类型、CMake 跨目录链接标记、CEF 多继承类型歧义、Unicode Bootstrap 入口、Sandbox ACL 部署参数及 Qt 间接 DLL 缺失。最初一次桌面 Smoke 因缺失运行时超时；补齐自动依赖部署后，Debug 和 Release 的启动/关闭测试均通过。

本地详细日志位于 `out/*-build.log`、`out/frontend-check.log` 和各构建目录的 `Testing/Temporary/LastTest.log`，均为忽略的可再生产物。桌面输出内的 `qt-runtime-dependencies.txt` 记录实际解析的依赖。

- M1 的完整 Renderer 崩溃恢复、关闭超时与异常生命周期矩阵尚未实现/验收；当前 Smoke 只验证正常启动关闭。
- M3 的真实 JSON 字节解析、Envelope 大小限制、路由、响应/事件、重复请求和取消协议尚未实现。C++ Fixture 转为值树后验证，不将其表述为真实 Transport 测试。
- Workspace/Document 实际文件能力、Monaco、TeX、PDF.js、SyncTeX、设置和会话恢复属于后续阶段；本次未安装 TeX。
- 未执行 clang-tidy（PATH 未发现该工具），未进行 Windows 10/11 多机矩阵、DPI 视觉验收或性能基准。
- 桌面目录是开发验收产物；完整依赖许可证集合、安装包和干净机器分发验证仍属 M8，不能据此宣称发布就绪。
- Shell/平台之间采用主线程生命周期端口的决定与迁移路径见 ADR 0001。
