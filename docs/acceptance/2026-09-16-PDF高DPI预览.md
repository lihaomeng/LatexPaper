# PDF 高 DPI 预览修复

## 实现

- Preview Feature 内新增 `pdfRaster.ts`，统一首帧、翻页和缩放的 Canvas 渲染。
- 分离 CSS 页面尺寸和内部像素尺寸，按设备像素比生成画布，并通过 PDF.js render transform 绘制。
- 首帧使用当前缩放及 DPI；加载期间参数变化时重绘后再提交，不先发布固定 1 倍的低清图。
- 通用 `useDevicePixelRatio` Hook 监听 resolution media query 和 resize；切换显示器或系统缩放后触发重绘，卸载移除监听器。
- SyncTeX 双击和标记使用已提交帧的逻辑尺寸、页码与缩放，不使用高清画布像素直接换算，避免 DPI 倍率造成偏移。
- 单画布最多 16,777,216 像素、单边最多 8192 像素；超过预算时降低内部采样倍率，但不改变页面显示大小。此限制不是整个 PDF.js 进程的内存上限。
- 成功/取消/失败后释放离屏画布像素，继续保留新帧完成后替换旧帧的行为。

## 边界

仅修改前端 Preview Feature 与通用显示 Hook，不改变 TeX、PDF Artifact、RPC 或原生编译模块。保留工作区已有项目切换修改和 paper1 文件。

## 验证

- 默认仅执行 `scripts/build.ps1 --dev`，不编译测试目标、不运行 CTest 或 npm test。
- 新增 `web/tests/pdfraster.test.ts`：DPR 1/1.25/1.5/2、像素预算和非法尺寸；按用户规则未执行。
- 完整 --dev 脚本退出码 0；TypeScript、Vite、原生链接及 MiKTeX Runtime 部署通过，输出 BUILD SUCCEEDED。架构检查 66 个 Target 通过。既有 CEF/VS 版本建议、Vite 大块体积和 MiKTeX 更新提醒仍存在。
- 未进行实际桌面高 DPI 截图对照或多屏人工验收，不据构建通过声称视觉验收完成。

## 人工验收步骤

1. 启动最新 `out/desktop-release/bin/Release/LightOverLeaf.exe`，打开 paper1 并编译。
2. Windows 缩放 125%、150%、200% 时查看正文、公式及表格；页面显示大小应保持对应预览倍率，文字边缘应较旧版清晰。
3. 预览倍率 100%、125%、200%、300% 之间切换，检查翻页和连续缩放无旧帧覆盖新帧。
4. 将窗口移动至不同 DPI 显示器，检查自动重绘。
5. 在不同倍率下双击文字回到源码，再从源码定位 PDF，确认标记不按 DPI 倍率偏移。

本次修复针对预览栅格分辨率，不改变 PDF 内嵌字体和原始位图质量。
